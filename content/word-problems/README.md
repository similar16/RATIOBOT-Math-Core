# 方程应用题：教材目录、补充练习与统一流程

本目录记录人教版七年级上册第五章的原题核验及合并决定。依据用户上传 PDF 逐页核验印刷页 110—148；版本以文件及 SHA-256 为准，不根据文件名猜测印次。

## 本次收录

80 组应用及建模题中，44 组保留为独立互动题，36 组高度相似题归入已有代表题。原有补充练习 27 题与新增 44 题合为 71 题。苏科版保留原书中的 81 个出现位置，对应 79 个分析任务；重复出处分别显示位置卡片，共用同一题目和学习记录。最终共 150 题、160 条设元路线。

`pep-ch5-coverage.json` 保留全部 93 条原始来源记录、39 页逐页审计、原表格、图形条件和 2 个题组内部的非一次小问。每条记录均有 `implementation`，说明独立收录、相似合并、同题复现或保留为边界参考。`similar-model` 只表示关系结构接近，不表示题目数据、情境或附问完全相同。

合并题的标题、页码及差异说明同时放入运行时索引，能通过原题页码搜索代表题，也能在代表题的“合并题目与出处”中查看。不同变式不互相继承完成状态。

## 两种目录与统一互动

`site/word-problems/catalog.js` 的 `forBook` 分开生成两种目录。苏科版教材按章引入、4.1、4.2、4.3、数学探究、小结与思考、复习题七组，依印刷页及题目顺序排列；其中 I11 参考题回到第 110 页相应位置。补充练习按 13 个题型：和差倍分、调配与盈不足、年龄问题、总价与数量、生产与配套、增长／利润／含量、工程与工作量、行程问题、方案比较与分段计费、几何数量、数字与图形规律、统计与计分、开放探究与方法边界。返回目录保留来源、筛选和搜索状态；教材搜索按当前出处定位。

所有代表题使用六页流程：读题找量 → 设元与推导 → 填写数量表 → 等量关系与列方程 → 草稿纸解方程并确认答案 → 检验。原来的“列方程”移到“找等量关系”下方；数值答案在草稿纸下方核对，最后一页仅做原条件与实际意义检验。手写草稿不自动评分。内部保留旧证据 ID 3、4，在同一建模页一起通过，界面只显示六页；v4 进度迁移保留已有答案、历史记录和个人草稿标识，旧草稿阶段不会自动当作答案已确认。

题目中的数学数据进入读题填空；派生数据先显示来源算式。首页“列式优先原则”说明“能用加法不用减法，能用乘法不用除法”。两组例子分别对比进价＋利润＝售价与售价－进价＝利润、标价×折扣倍数＝售价与售价÷标价＝折扣倍数，并明确同组两种写法均成立，列方程时优先用加法、乘法；数据来源示范包括 `1÷12=1/12`、`1+25%=1.25` 和 `8÷10=0.8`。折扣推导同时给出“标价每10元，实际付8元”的解释。数量表以对象、阶段或状态为行，以具体数量和单位为列。加和／乘积关系使用二元三格模板，关系行顺序、两加数及两乘数的次序均可交换。

条件在正确找到后固定到左侧清单，可逐条标为已用并再次点击恢复。完成推导、填表和列式会标记所用条件；检验完成后全部显示为已核对。条件清单是可回看的使用记录，不代替数学校验；找到与标记状态随当前账号进度保存。

`data-pep-foundations.js`、`data-pep-applications.js`、`data-pep-review.js` 只按维护职责拆分，学生目录不按这些文件或原课时排列。每条路线通过 `relationTriples` 提供数量卡片，既有题继续使用原关系注册表。

## 数量表的多种正确表示

`engine.checkTableCell` 支持恒等展开、合并同类项、加数或乘数交换、分数与小数互换，并保留来源算式到学生写法的链条。派生数值仍须先通过来源计算；任意无来源的新数、额外变量或只在最终答案处碰巧相等的表达式不能通过。

`table-alternatives.js` 显式登记另一题设对同一数量的表示：审查全部 150 题、160 条路线，为 123 题、132 条路线的 302 个格子增加 302 条替代。每项标明来源及列式提示，例如羽绒服售价可由折扣表示，也可用进价加96元表示。运行时只查登记表，不读取最终解；教师指定“按差表示／按倍数表示”的列仍按列义填写。未登记跨条件替代的路线仍接受恒等变形。

列式页保留学生的实际表格写法，可直接取用。删除“选择列式依据”的重复勾选；原条件与替代条件都可用于形成独立方程。检查通过后自动标记所用条件，并在标题下提示可点击表格中的“取用此量”。每个方程仍须通过严格的代数与数值来源校验，恒等式不能过关。

## 输入框与保存密码提示

`credential-forms.js` 将 7 个密码／PIN 控件归入 5 个独立凭证表单，阻止原生表单提交，保留原登录按钮和 Enter 处理。数学输入、读题填空及文字答案添加关闭自动填充与密码管理器忽略提示。目的是避免浏览器把练习输入与隐藏的登录控件混为同一表单；网页无法强制关闭浏览器对真实登录凭证的保存密码设置。

## 数学与交互边界

- P051 由原表推出每次文艺活动 2 小时、科技活动 1.5 小时，然后对 `2x + 1.5y = 7` 做非负整数筛选。答案各 2 次可自动核验，文字论证提交课堂讨论，不伪造一元一次关系。
- P068 保留实验及参数方程 `nx = l/2`，`n` 与 `l` 标为已知参数。当前符号引擎不自动评分含参数系数的列式，故保存文字模型供课堂讨论；这不是非一次问题。
- 分段费用的候选解必须回到区间和整数条件检验；原题“满 100 减 50”只减一次；“提高 10 个百分点”使用 `40% + 10%`，不按相对增长率计算。
- 原有题号、设元路线和账号进度结构不变；不新增进度别名。原题只要求列式的内容与延伸求解分别说明，草稿纸承接学生实际输入的方程。

## 验证

`npm run test:word-problems` 同时保留既有题库、数值来源、关系拖拽、草稿纸、进度隔离及账号桥接测试，并加入教材顺序、跨题设替代、六页迁移和条件清单测试。UI 测试通过真实 DOM 事件逐条完成全部 160 条设元路线，检查统一流程、两种目录、来源表格和返回状态，并覆盖羽绒服、壶杯及双人计分的混合填表与列式。`npm test` 另验证独立凭证表单及原登录控件。

发布验证执行 `npm run build`、`SITE_DIR=_site npm test` 及 `SITE_DIR=_site python tests/assets.py`。线上入口保持原有登录要求；视觉复核应在可登录的真实站点进行。本次浏览器环境未能打开隔离本地预览，不能将自动交互测试表述为桌面与手机截图验收。此目录不包含用户账号信息或学生作答数据。
